# Отчёты, диалоги, звук и выход из квартиры

Добавлен runtime-модуль C++ `Dostoevsky`. Карты, персонаж и GameMode сохранены. В двух HUD Blueprint заменена отрисовка старых реплик; оформление и совместимость описаны в [DialogueStyle.md](DialogueStyle.md).

## Первая сборка

1. Закройте Unreal Editor. Нужны инструменты C++ MSVC, Windows SDK и .NET Framework SDK. На текущем компьютере сборка уже проходит с MSVC 14.52 и Windows SDK 10.0.26100.0.
2. Из корня репозитория выполните `powershell -File Scripts/BuildEditor.ps1`. При другом расположении движка добавьте `-EngineRoot "путь-к-UE_5.8"`.
3. При необходимости создайте конфигурацию VS Code: `powershell -File Scripts/BuildEditor.ps1 -GenerateVSCode`.
4. Откройте `Dostoevsky.uproject`. Для первой сборки новых отражаемых C++-классов используйте полную сборку, а не Live Coding.

Отсутствие Binaries и Intermediate в Git нормально: каждый участник собирает их локально. После добавления C++ коллегам тоже нужны инструменты сборки.

## Общее окно взаимодействия

`UInteractionDocument` — Data Asset с Title, Speaker, Body, CloseLabel, OpenSound, Voice, CloseSound. Новое оформление, шрифты и совместимость со старым HUD описаны в [DialogueStyle.md](DialogueStyle.md). Все DocumentWindow используют этот единый дизайн.

## Подключение нового объекта

Существующие отчёт и диалоги уже подключены через обновлённые HUD. Следующие шаги предназначены для новых объектов; не подключайте второй обработчик к тому же событию.

1. В Blueprint нового объекта добавьте `NarrativeInteractionComponent` через Add Component.
2. Создайте Data Asset класса `InteractionDocument` (например, `DA_NewReport`), заполните Title/Speaker/Body и назначьте его в Document. Оставьте `bExitToStreet` выключенным.
3. Из вашего существующего события взаимодействия вызовите `ActivateInteraction`, передав PlayerController взаимодействующего игрока.
4. Подключайте один обработчик открытия окна к событию взаимодействия, чтобы не создавать две панели.

Компонент не назначает клавишу E, не меняет персонажа и не реализует луч поиска: он подключается к уже существующей системе взаимодействия. Возвращаемое `false` означает, что действие не запущено. Та же схема подходит для следующих документов и реплик.

## Подготовка звука

Импортируйте записи в Content/Audio, например подпапки UI, Voice, Ambience. Для документа назначьте звуки открытия, закрытия и озвучку в его Data Asset. Озвучка останавливается при закрытии или замене документа; не создаёт наложения нескольких реплик. Музыку и UI-звуки сводите по громкости в самих звуковых assets/Sound Classes.

Фон запускается так: `Get Game Instance Subsystem (NarrativeSubsystem)` → `StartAmbience(Sound, Volume)`. Вызовите это в BeginPlay нужной локации. Для бесконечного фона настройте looping в Sound Wave / Sound Cue / MetaSound. `StopAmbience(FadeSeconds)` позволяет плавно завершить фон. При выходе на другую карту фон останавливается сразу, чтобы не переносить звуки квартиры на улицу.

Загрузочный экран не воспроизводит музыку: текущая основа не обещает непрерывный звук во время блокирующей загрузки. Записей, лицензированной музыки и готовых звуковых assets в поставке нет.

## Выход на улицу Американского квартала

1. Создайте и сохраните реальную карту улицы, например `/Game/Street/L_AmericanQuarterStreet`, и добавьте PlayerStart и нужный GameMode.
2. Добавьте `NarrativeInteractionComponent` к Blueprint выходной двери.
3. Включите `bExitToStreet`, назначьте реальную карту в StreetMap и заголовок «Улица Американского квартала» в StreetTitle.
4. Из взаимодействия двери вызовите `ActivateInteraction(PlayerController)`.
5. В Project Settings → Packaging → List of maps to include in a packaged build добавьте карту улицы. Сейчас в конфигурации упаковки явно указаны только две карты квартиры. Не добавляйте несуществующую карту.

Система проверяет существование карты до закрытия окна и запуска перехода. Пустая/неверная ссылка возвращает false и пишет предупреждение в Output Log. Повторный переход во время загрузки блокируется. После успешного перехода состояние сбрасывается; ошибки travel логируются и снимают блокировку.

Во время OpenLevel используется Slate/MoviePlayer: тёмный экран, название места, индикатор и «Загрузка…». Это индикатор ожидания, а не процент загрузки. Минимальная длительность — 1 секунда. Проверяйте MoviePlayer в Standalone Game или упакованной игре: в Play In Editor отображение не гарантируется. Карта улицы кодом не генерируется, актёры и инвентарь между картами автоматически не сохраняются.

## Проверка после сборки и подключения

- Открыть отчёт: текст читается, длинный текст прокручивается, движение и обзор заблокированы.
- Закрыть кнопкой и Escape: окно исчезает, курсор и управление возвращаются, голос останавливается.
- Открыть другой документ: появляется его текст и звук без наложения озвучки.
- Вызвать выход с пустой картой: персонаж остаётся в квартире, есть предупреждение.
- В Standalone выйти с назначенной картой: показан загрузочный экран, затем улица с работающим персонажем.
- Собрать Development-пакет с обеими картами и повторить выход. Проверить обратный переход, если он нужен.

Эти проверки требуют Unreal Editor и назначенных assets; статическая подготовка файлов не означает, что интеграция в существующие Blueprint уже выполнена.
